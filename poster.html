Final year project

Local Multimodal File Search

Find your files by what is inside them — not by their name

100% OFFLINE NO SERVER NO ACCOUNT ONE WINDOWS INSTALLER

The problem

Windows Search finds filenames. It cannot find meaning.

A scanned certificate saved as IMG_20230417.pdf is invisible to every search tool on the machine — the page is a picture, so there is no text in the file at all.

The objective

Search personal PDFs, Word documents and images by their content, using ordinary language, entirely on one Windows laptop — with no internet connection, no account and no cloud service.

02ExtractText and page images from PDF, DOCX and image files
03Chunk and filterSplit into passages; discard those with no retrievable content
04Embed and indexbge-large → 1024-dim vectors → Qdrant, plus the FTS5 keyword index
05Read and describePaddleOCR on GPU · moondream2 captions · CLIP image vectors
06ReadySearchable by text, by picture, and by exact number
pending→ extracting→ extracted→ processing→ ready Work is prioritised so a file becomes findable in about a second, while slower image processing continues behind it.

How a question gets answered

“outward reference 42595078122”
Retriever A Meaning, in text Matches passages by sense rather than by keyword, so the words you type need not appear in the document. bge-large-en-v1.5 · cut-off 0.55
Retriever B Meaning, in pictures Places images and text in one shared space, so a description can be matched directly against a photograph. OpenCLIP ViT-H/14 · cut-off 0.22
Retriever C Exact words and numbers A literal keyword index for reference numbers and codes, which meaning-based search cannot find at all. SQLite FTS5 · identifiers required
three ranked lists
Reciprocal Rank Fusion Merged by position in each list, not by score — the raw numbers are discarded deliberately. 1 / (60 + rank)
Group by fileStrongest passage becomes the headline; the rest attach as supporting evidence
Relevance floorWeak results dropped; when the best match is marginal, the app says so
Ranked resultsTitle, snippet, thumbnail, page number and match strength — ten per page

Three decisions, each measured

Separate spaces Text and image vectors are stored in two collections, never one. Both are 1024 numbers wide, but they are different spaces. Searching across a mixture returns noise — and nothing about the results looks wrong.
Rank, not score Results are merged by position, because the two models' scores are not comparable. A good text match scores 0.70. An equally good image match scores 0.25. Comparing them directly puts every text result above every image result.
Keywords still matter Meaning-based search cannot find a reference number. The passage literally containing the number scored 0.45; an unrelated document scored 0.57. The right answer ranked below the noise — an inversion no threshold repairs. A keyword index solves it.
